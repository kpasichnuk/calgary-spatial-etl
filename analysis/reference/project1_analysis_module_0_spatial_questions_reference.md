# Analysis Module A0: Spatial Questions and Decision Value

## Objective

Learn to translate a broad topic into a bounded spatial question connected to a stakeholder decision.

## From Topic to Question

`Transit in Calgary` is a topic. It does not identify a comparison, method, unit, or decision.

A bounded question is:

> How does mapped transit-stop density vary among Calgary communities in the current ETL snapshot?

It identifies points, polygons, a comparison, a study area, and a data state.

## Stakeholder and Decision

Assume a planning analyst wants to prioritize communities for deeper investigation. The first analysis is a screening tool, not a service recommendation.

A useful analytical product narrows uncertainty or attention for that user.

## Hypothesis

Write an expected pattern before computing. For example, raw counts may favor larger communities while area-normalized rankings differ.

A hypothesis is not a desired result. It is a prediction that can be contradicted.

## Supported Scope

Current inputs support:

- assignment of mapped stops to community polygons
- raw stop counts
- projected community area
- stops per square kilometre
- comparison and ranking with caveats

They do not support claims about population, demand, frequency, travel time, equity, or service quality.

## Analysis Contract

Write these fields before coding:

- stakeholder
- decision
- spatial question
- unit of analysis
- numerator
- denominator
- spatial relationship
- expected output
- limitations

## Completion Criteria

You can complete this module when you can distinguish a topic, operation, question, result, and decision; write a falsifiable hypothesis; and reject claims unsupported by the available data.
